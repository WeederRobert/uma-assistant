# 卡池模块（排期 / 精选 / 预告）

`modules/gacha` 从本机 `master.mdb` 读**客户端内置的卡池排期**，所以能看到尚未开放的未来卡池 —— 「下一期是什么」不需要外部公告来源。这推翻了此前「卡池提前预告只能接公告源」的判断。

> **这个模块不单独占一页**：面板并入侧栏「日程」（与大赛排期、BWiki 活动时间轴同页），本模块只提供 `/api/gacha` 接口。日程页通过 HTTP 调它，任一模块不可用时那一段降级成提示，不影响其它内容。

## 数据来源

全部来自 `master.mdb`（可信级别 A：客户端原始数据）。

| 内容 | 来源表 | 说明 |
| --- | --- | --- |
| 卡池主记录 | `gacha_data`（348 行、48 列） | 只取 `id` / `type` / `card_type` / `start_date` / `end_date`，其余 40 多列是「抽一发给什么」的数值，本模块不用 |
| 卡池名称 | `text_data` 26 | 348 / 348 都有，如「精选 优俊少女招募」「3★必得新人出道招募第1期」 |
| 卡池说明 | `text_data` 13 | 348 / 348 都有，如「期间精选协助卡的出现率提升！」 |
| 精选卡片 | `gacha_available`（43069 行）`is_pickup = 1` | 一个卡池内的所有卡片都在这里，只有 `is_pickup = 1` 才是精选 |
| 马娘卡名称 | `card_data` + `text_data` 6 / 5 | `card_type = 1`，1858 / 1858 解析成功 |
| 协助卡名称 | `support_card_data` + `text_data` 6 / 76 | `card_type = 2`，1734 / 1742 解析成功（8 条在当期快照里没有对应卡） |

### 与 BWiki 的交叉验证

简中服 2.0.2 快照里 `gacha_data.id = 30204` 是 `2026-10-24 12:00 → 2026-11-03 11:59`、精选「跳舞城[GLITTER！]」，与 BWiki 简中服当期卡池「3★跳舞城 优俊少女招募」逐字一致；`30203` 的起止时间也与 BWiki「超稀有万籁争鸣、稀有极峰 协助卡招募」一致。**结论：mdb 的卡池排期就是简中服的实际排期。**

### 能提前多久

2026-10-27 的库内实测：348 个卡池里 **41 个在未来**（另有 3 条是未定档占位，见下），最晚到 **2027-01-18**。客户端每次更新都会带上后续一两个月的排期，所以「提前预告」的窗口＝客户端有多新，而不是公告什么时候发。

## 字段口径

| 字段 | 取值 | 处理 |
| --- | --- | --- |
| `gacha_data.type` | 1 / 2 / 3 / 5 / 10 / 11 / 12 / 13 / 14 | **没有字典表**，只回显「类型 N」。同样是精选池也会出现不同编号（3 = 常规精选 251 个，11 = 闪耀精选 6 个…） |
| `gacha_data.card_type` | 1 / 2 | 1 = 马娘卡、2 = 协助卡。依据是「能否 JOIN 到 `card_data` / `support_card_data`」：1 全部命中、2 命中 99.5% |
| `start_date` / `end_date` | unix 秒 | 按**运行环境的系统时区**展示（`app.kernel.times.local_iso`） |
| 常驻池 | `end_date` 落在 2050 哨兵 且跨度 > 5 年 | 新人出道 / 通用招募这类池子把 `end_date` 写成 `2050-01-01`（一个「不结束」哨兵值），标为「常驻」并显示「记录结束时间 2050-01-01」，不显示「还剩 10592 天」。当期快照里 23 条远期记录中 20 条属于这类 |
| 未定档占位 | `start_date` 落在 2049 / 2050 | 客户端里已经存在但还没排期的池子（如 `30130` / `30131` 的开始与结束都在 2050-10、`20013` 从 2049-12-28 起）。它们**不进「即将开始」**，单独列在「未定档」，否则会显示「还有 8800 天开始」。当期快照里有 3 条 || `gacha_available.is_pickup` | 0 / 1 | 只导入 1 的行；必得 / 自选类卡池可能没有精选标记，面板显示「无精选卡片」 |
| `select_pickup` | 305 行 | 「自选池」的可选范围，与 `is_pickup` 是两个概念，本模块**不混用**，见已知限制 |

哨兵阈值统一用 `modules/gacha/importer.py` 的 `SENTINEL_TS = 2_500_000_000`（≈ 2049-03-22），导入时数「未来卡池」与展示时判「常驻 / 未定档」共用同一个值，避免两边口径漂移。

## 数据表

两组表，前缀 `gacha_`：

| 表 | 用途 |
| --- | --- |
| `gacha_catalog` | 卡池：`gacha_id`、`type`、`card_type`、名称、说明、`start_ts`、`end_ts` |
| `gacha_pickups` | 精选卡片：主键 `(gacha_id, card_type, card_id)`，含 `rarity` / 名称 / 称号 / `recommend_order` |

来源元信息写在 `meta` 的 `gacha.catalog_source`：mdb 路径与 sha256 前缀、`mdb_mtime`、导入时间、卡池数 / 未来卡池数 / 精选条数。`mdb_mtime` 是「数据是不是旧了」的判据，`master.mdb` 更新后启动会自动补导入。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/gacha/status` | 卡池数、精选条数、未来卡池数、导入来源与时间、`stale`、mdb 路径与大小、时区、口径说明 |
| GET | `/api/gacha/banners?include_ended=true&limit_ended=20` | 四组：`upcoming`（按开始时间升序）/ `active` / `ended`（按结束时间倒序，默认 20 条）/ `unscheduled`（未定档占位） |
| GET | `/api/gacha/banners/{gacha_id}` | 单个卡池详情，含精选卡片 |
| POST | `/api/gacha/refresh?force=false` | 重新导入；mdb 缺失返回 422 |

每个卡池带 `state`（`active` / `upcoming` / `ended` / `unscheduled`）、`permanent`、`starts_local` / `ends_local`、`days_to_start` / `days_left`、`type_label`（「类型 N」）、`card_type_label`、`pickups[]`。`counts` 里另有 `permanent` 与 `unscheduled` 两个计数。

## 面板

面板在侧栏「日程」页的「卡池（master.mdb 排期）」卡里：

- **工具条**：「刷新卡池排期」（`POST /api/gacha/refresh?force=true`）、「显示最近已结束」（默认关）、当前条数与时区。
- **即将开始（N）**：按开始时间列出未来卡池，「还有 N 天开始」+ 起止时间 + 精选卡片标签（马娘 / 协助卡 + 名称 + 称号）与卡池说明；没有未来卡池时说明「客户端未更新到最新版本时不会提前出现」。
- **精选数量**：每行默认只列 4 张，剩下折成可点的 `+N`；点开后显示全部（最多见过 68 张，如「3★ WISH&GAZE 招募」），按钮变成「收起」。展开状态按 `gacha_id` 记在面板里，翻页 / 勾选「显示最近已结束」重渲染后不会丢。
- **进行中（N）**：当前开放的卡池，常驻池标「常驻」并写「长期开放」。
- **未定档（N）**：仅当存在这类记录时出现，说明「日期是客户端占位值（2049 / 2050），不是真实排期」。
- **最近已结束**：勾选后显示最近 10 个。

同一页还有「大赛（群英联赛）」卡（默认只看未结束）与 BWiki 抓取的活动时间轴，三者共用系统时区。

## 已知限制

- **`type` 含义未知**：主数据里没有 `gacha_data.type` 的字典表，面板只写「类型 N」。要把它翻成「常规精选 / 必得 / 阶梯」需要外部资料，不猜。
- **预告来自客户端，不是官方公告**：游戏临时改动（提前开池、改名单）而客户端没更新时会与实际情况不符；面板与文档都写明「以游戏内公告为准」。
- **窗口取决于客户端版本**：当期快照能看到未来约两个月（最晚 2027-01-18）；客户端越旧，能看到的未来越少，甚至没有。
- **自选池的可选范围没有展开**：`select_pickup`（305 行）是「自选 / 交换」范围，和 `is_pickup` 不是一回事；本模块只展示精选标记，混用会把「可选范围」误当「本次提升概率的卡」。
- **8 条协助卡精选解析不到名称**：`card_type = 2` 的 1742 条精选里有 8 条在当前快照的 `support_card_data` 里找不到，面板显示「未收录 #卡id」而不是编名字。
- **2050 是哨兵不是排期**：`end_date = 2050-01-01` 表示「不结束」（常驻池），`start_date` 落在 2049 / 2050 的是未定档占位。这两类都不能按日历理解，面板分别标「常驻」与「未定档」；如果以后客户端换了哨兵值（比如改到 2100），需要同步改 `SENTINEL_TS`。
- **不含概率与消耗**：`gacha_odds` / `rarity_odds_id` / `cost_single` 等数值列没有导入。抽卡概率与付费信息属于商业内容，需要单独的口径确认再决定是否展示。
