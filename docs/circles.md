# 社团（实验性）

读取第三方站点 [umamusume.space](http://umamusume.space/uma/) 的公开 JSON 接口，展示**社团当月增粉**与**成员贡献占比**。

> 这个模块是实验性的：数据由第三方玩家自采，不是官方数据，接口没有文档也没有 SLA。站点改版或停更时模块会失效（接口返回 422），已有缓存仍可查看。

## 1. 数据来源

| 用途 | 接口 | 体积 | 说明 |
| --- | --- | --- | --- |
| 社团月榜 | `GET /uma/api/circles` | 约 100 KB | 约 160 个被站点跟踪的社团，含 `month_delta` / `today_delta` / `ranking_rank` |
| 成员明细 | `GET /uma/api/circles/{circle_id}` | 约 1.4 MB | 含 `members[]`、`month_baseline_at`、`capture_interval_minutes` |

- 站点是第三方玩家自建服务，**不是官方接口**；它自己的采集端每小时抓一次游戏内社团成员列表，再用快照差分出「当月增粉」。
- 接口无鉴权、无 CORS 头、**只提供 HTTP**（无 HTTPS 端点）。
- 未被站点收录的社团，详情接口返回 `404 {"detail":"Tracked circle not found"}`。

## 2. 口径

| 字段 | 来源 | 口径 |
| --- | --- | --- |
| 当月增粉 | 列表 `month_delta` | 站点用「当月 1 日 05:00 的总粉丝快照」与当前快照做差；**不是游戏内直接给出的字段** |
| 当日新增 | 列表 `today_delta` | 以当日 05:00（游戏换日）为基线 |
| 成员当月增粉 | 详情 `members[].month_fan` | 同一套差分口径，按成员计算 |
| 贡献占比 | 本模块计算 | `成员当月增粉 ÷ 本社成员当月增粉合计`；分母用成员合计，不用榜单值 |
| 差值 | 本模块计算 | `榜单当月增粉 − 成员合计`，**不摊平**；来自成员进出与双方快照时间差，实测约 0.0x% |
| 日均 | 详情 `daily_avg` | 站点给的月内日均 |
| 本月育成 | 详情 `month_training_count` | 站点按育成次数差值计算 |
| 最后登录 | 详情 `last_login_time` | 站点快照里的时间，按系统时区展示 |

`viewer_id`（玩家账号 ID）只用于成员去重，**不进接口、不进面板**。

## 2.5 为什么模块只认 `circle_id`

社团**名字不是键**：玩家可以随时改名，而且会重名——站点收录的 159 个社团里就有两
个都叫「颂乐人偶」（`150952970` / `264444677`），另有 11 个名字带「招人 / 收人」后缀。
`circle_id` 才是稳定标识，由服务端在建团时分配，改名不变。

从站点数据能看到的特征：

| 观测 | 结果 |
| --- | --- |
| 位数 | 全部 9 位，实测范围 `110231887` – `995520409` |
| 分布 | 首位 1–9 大致均匀（13–24 个/段），不像从 1 开始顺序自增 |
| 与创建时间 | 不严格对应（`971337917` 的社团 2023-08 就已有成员加入时间） |
| 与玩家 ID | 两套独立序列：`circle_id` 9 位，`viewer_id` 12 位 |

所以「按名字查 ID」不可靠。已知的三条获取路径：站点列表（`GET /uma/api/circles`
名字 ↔ ID）、社团招募信息、游戏内按 ID 搜索的入口。站点未收录的社团，即使知道 ID
也只会拿到 404，需要先去站点侧（QQ 群）申请收录，收录后重新拉取月榜即可，模块无需改动。

## 3. 存储

| 表 | 内容 |
| --- | --- |
| `circles_circles` | 榜单级：一行一个社团，`month_fans` 即列表的 `month_delta` |
| `circles_members` | 成员级：`(circle_id, viewer_id)` 主键，存当月增粉、总粉丝、日均、育成次数、最后登录 |
| `circles_meta` | 最近一次拉取时间、当月基线、站点采集间隔 |

列表刷新以站点当前的跟踪名单为准：新社团写入，站点已下线的社团连同其成员明细一起删除。成员明细按社团整体替换，退会成员不会残留。

## 4. 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `GET` | `/api/circles/status` | 已存社团 / 成员数、最近拉取时间、当月基线、缓存时长 |
| `POST` | `/api/circles/refresh` | 拉取社团月榜（不拉成员明细）；失败返回 422 |
| `GET` | `/api/circles?q=&sort=month\|today\|rank&limit=` | 列表；`q` 匹配社团名或社团 ID |
| `GET` | `/api/circles/{circle_id}?refresh=true` | 成员明细与贡献占比；本机无该社团时 404，拉取失败且无缓存时 422 |

成员明细默认缓存 `UMA_CIRCLES_MEMBER_CACHE_MINUTES`（10 分钟）；带 `refresh=true` 强制重新拉取。拉取失败但有缓存时返回缓存，并带 `stale: true` 与说明文案。

## 5. 面板

侧栏「社团」，页面上标「实验性」：

1. **数据来源卡**：接口地址、上次拉取、当月基线、站点采集间隔、已存数量、刷新按钮。
2. **社团月增粉丝表**：月榜名次、社团（含 ID）、成员数、当月增粉、当日新增；每行可拉取该社成员。
3. **成员贡献卡**：榜单当月增粉、成员合计、差值、成员数 / 有贡献人数、人均当月增粉、成员明细时间；逐成员列出当月增粉、贡献占比（含占比条）、日均、本月育成、最后登录。

首次进入且本机没有数据时，面板会自动拉一次社团月榜。

## 6. 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `UMA_CIRCLES_BASE_URL` | `http://umamusume.space/uma/api` | 接口前缀 |
| `UMA_CIRCLES_TIMEOUT_SECONDS` | `30` | 单次请求超时 |
| `UMA_CIRCLES_USER_AGENT` | `uma-assistant/1.0` | 请求 UA |
| `UMA_CIRCLES_MEMBER_CACHE_MINUTES` | `10` | 成员明细缓存时长 |
| `UMA_CIRCLES_LIST_LIMIT` | `300` | 列表默认返回上限 |

## 7. 已知限制

- **只覆盖站点收录的社团**（约 160 个）。自己的社团没被收录时，只能看到 404 提示；收录入口在站点侧栏的 QQ 群。
- **站点停更 / 改版即失效**：接口不是官方契约，字段名变动会直接表现为 422。
- **首拉较慢**：成员明细单次约 1.4 MB、约 2 秒；已用本地缓存降低重复请求。
- **只走 HTTP**：数据在传输中不加密，且不含任何账号信息。
- **人数与贡献以站点快照为准**：站点按小时采集，同一分钟内多次观察到的数字可能不同。
- 不提供「按月归档」：站点另有 `monthly-reports/{YYYY-MM}` 接口，本模块暂不接入。

## 8. 验证

```powershell
uv run ruff check modules/circles tests/test_circles.py
uv run pytest tests/test_circles.py
```

启动后：

```powershell
curl -s -X POST http://127.0.0.1:8737/api/circles/refresh
curl -s "http://127.0.0.1:8737/api/circles?limit=3"
curl -s "http://127.0.0.1:8737/api/circles/264444677"
```

面板在侧栏「社团」，能搜到「颂乐人偶」并展开成员贡献即视为通过。
