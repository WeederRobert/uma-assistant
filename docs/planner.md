# 规划模块（千里眼 / 萝卜规划）

`modules/planner` 回答两件事：**接下来半年有哪些卡池与剧情活动**（千里眼），以及**手上的萝卜够抽哪些**（规划）。
数据来源、口径与限制都写在这里，面板只做展示。

## 一条前提：简中服在加速，日服时间对不上轴

简中服内容推进比日服快，而且还在继续加快。2026-11-01 用本机 `master.mdb` 的已确认排期实测：

| mdb 实际开池 | BWiki 预测（日服对轴） | wiki 偏晚 |
| --- | --- | --- |
| 2026-10-24 跳舞城 | 2026-11-28 | +35 天 |
| 2026-10-29 「目白晚会」活动池 | 2026-12-08 | +40 天 |
| 2026-11-05 里见皇冠 | 2026-12-19 | +44 天 |
| 2026-11-14 高尚骏逸 | 2026-12-28 | +44 天 |
| 2026-11-16 北部玄驹 | 2027-01-05 | +50 天 |
| 2026-11-23 | 2027-01-17 | +55 天 |

偏差**不是固定值**，而是随日服日期递增（每过一个月多晚几天）。所以：

- 不能用「日服 + 某个常数」换算（wiki 页面上写的 −185 / +423 天这类历史账更不能抄）；
- **活动不做跨服换算**：简中服的活动顺序与日服并不一致，对轴没有意义。

## 数据来源

| 段 | 来源 | 获取方式 | 级别 |
| --- | --- | --- | --- |
| 已确认卡池 | 本机 `master.mdb` 的 `gacha_data` / `text_data` / `gacha_available` / `gacha_exchange` | `mode=ro` 只读打开，按 `sha256` 判断要不要重新导入 | A（游戏本体数据） |
| 已确认剧情活动 | 本机 `master.mdb` 的 `story_event_data`（名称取 `text_data` 214，回退 189） | 同上 | A |
| 预测卡池 | BWiki SMW：`[[分类:赛马娘卡池]][[简中::未实装]]` 的 `简中开始时间` / `简中结束时间` | 串行 + 1.5 s 间隔 + 6 h TTL 缓存，面板可强制刷新 | C（wiki 按日服对轴推算，**本项目再用 mdb 实测偏差校正**） |

`简中::未实装` 是 BWiki 自己的标记：「日服已经上线、简中还没实装」。它给的 `简中开始时间` 是
「日服 + 固定偏移」的推算值，**已经偏晚**，只能当原始素材；校正见下一节。

不抓 `分类:活动`：那里只有日服时间，且简中服的活动顺序与日服不一致，换算出来的日期没有意义。

## 偏差校正（预测段）

每次刷新都会重新量一遍「wiki 比 mdb 晚多少天」：

1. **配对**：mdb 已确认段的马娘池（`card_type = 1`）按精选角色 id 集合建索引；wiki 预测段只取
   `角色ID`（不含支援卡）的集合。两个集合完全相等、且该组合在 mdb 里只出现一次，才算一对干净样本。
   八骏 / 必得 / 自选这类多卡池会被自动排除。
2. **偏差** = wiki 预测日期 − mdb 实际日期。因为偏差随时间递增，平移量取**最近一次实测**的偏差
   （不是整段中位数——中位数会被早期的小偏差拖低、校正不足）；中位数与 `min_days` / `max_days` 一起回显作参照。
3. 预测行展示两个日期：**校正后**（参与规划、排序）与 **wiki 原值**（附「前移 N 天」说明）。

2026-11-01 实测 6 组样本：+35 → +40 → +44 → +44 → +50 → **+55** 天（按时间顺序），
平移量取最近一次 **+55 天**，区间 +35~+55。**这只是平移，不是趋势外推**：
偏差还在扩大，越远的预测即使校正过也可能仍偏晚，面板上必须保留这句提示。

## 分段：避免同一期被算两次

| `segment` | 含义 | 默认展示 | 进规划 |
| --- | --- | --- | --- |
| `confirmed` | `master.mdb` 里进行中或未来的普通池（排除常驻池与未定档占位） | ✅ | ✅ |
| `predicted` | BWiki 预测，且日期**晚于** mdb 已确认段的最后一刻（`horizon`），已按偏差平移 | ✅ | ✅ |
| `overlap` | BWiki 预测，落在 mdb 已确认段之内 —— 同一期卡池的两种描述 | ❌（勾选后折叠展示） | ❌ |

`overlap` 段是**量偏差的原料**，不是给人看的日程：它的日期是错的（wiki 原值），所以默认隐藏，
勾「显示与 mdb 重叠的预测行」才会出现在折叠区里做对照。

## 口径

| 项 | 口径 | 依据 |
| --- | --- | --- |
| 单抽成本 | `gacha_data.cost_single`（实测 150） | mdb 真实列 |
| 天井抽数 | `gacha_exchange.pay_item_num`（兑换本期 UP 卡需要的点数，实测 200） | mdb 真实列 |
| 天井萝卜 | 天井抽数 × 单抽成本 = 200 × 150 = 30000 | 上两列相乘；**「1 抽 = 1 点」这条规则不在 mdb 里**，见「已知限制」 |
| 预测池成本 | 取已确认段里出现最多的 `cost_single` / `ceiling_pulls`（众数） | 预测池不在 mdb 里，只能借当期口径 |
| 萝卜收入 | **用户自己填**的每月收入，按 30 天/月线性折算到每个目标池开始那天 | 库里没有任何收入数据，不估算、不外推 |
| 抽券 | 1 张 = 1 抽，优先于萝卜使用 | 用户输入，不区分有偿 / 无偿 |
| 买不起的目标 | 标「缺口」且**不扣账**（视为放弃，把萝卜留给后面的池子） | 否则会连带惩罚后面的池子 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/planner/status` | 条数、mdb 是否过期、偏差样本、成本口径、窗口天数 |
| GET | `/api/planner/forecast?days=180&include_overlap=false` | `pools`（含 `segment` / 校正后日期 / `source_starts_local` / `correction_days`）、`events`、`calibration`、`cost`、`counts`、`notes` |
| POST | `/api/planner/refresh` | body `{"force": true}`：重新导入 mdb 已确认段（卡池 + 剧情活动）并重抓预测卡池 |
| GET | `/api/planner/plans` | 已存方案列表 |
| POST | `/api/planner/plans` | 新建方案（`name` / `carats` / `tickets` / `monthly_income` / `targets`） |
| GET | `/api/planner/plans/{id}` | 方案 + 用它当前预测现算的评价（404 表示没有这个方案） |
| PUT | `/api/planner/plans/{id}` | 覆盖保存 |
| DELETE | `/api/planner/plans/{id}` | 删除 |
| POST | `/api/planner/evaluate` | 不落库的试算，body 同方案 |

`events` 只来自 mdb 的剧情活动（`source_level = A`），时间按系统时区换算；
`calibration` 给出 `pairs` / `bias_days` / `min_days` / `max_days` / `samples`。

## 已知限制

- **活动只有剧情活动**：`story_event_data` 覆盖剧情活动；育成活动（竞速嘉年华、大师挑战赛、目标！最强队伍）
  在客户端里没有可读的简中排期，不展示。群英联赛（大赛）排期看「日程」页。
- **剧情活动排期也有尽头**：当期快照覆盖到 2026-12-26，再往后没有数据。
- **预测段是「wiki 推算 + 实测平移」**：平移量取最近一次实测偏差（当前 55 天）。偏差随时间扩大
  （2026-10-24 时是 35 天，11-23 已到 55 天），靠后的预测即使平移过也可能仍偏晚；
  不做趋势外推，宁可保留 wiki 原值供对照。
- **偏差样本会变少**：一旦 mdb 的已确认段短于 wiki 预测段（例如客户端很久没更新），
  `calibration.pairs` 会变成 0，预测段退回 wiki 原值并给出提示。
- **「1 抽 = 1 点」不在 mdb 里**：`gacha_exchange.pay_item_num` 只给「兑换 Up 卡需要的点数」，
  点数怎么积累由游戏规则决定，本项目没有可核对的来源，天井萝卜按 1 抽 1 点算，面板写明这一点。
- **常驻池与未定档不参与**：`2050-01-01` 结束的常驻池、开始时间落在 2049/2050 的未定档占位都不进千里眼。
- **收入完全靠用户**：不内置任何「每月能攒多少萝卜」的估算，也不从活动/大赛反推收益。
