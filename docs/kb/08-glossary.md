## 核对方法

简中列不是翻译推测，而是从简中服 `master.mdb` 的 `text_data` 表里直接取出的官方文案：

```sql
-- text_data(id, category, "index", text)：id 与 category 恒等，"index" 指向实体
SELECT text FROM text_data WHERE category = 63 AND "index" = 7;   -- 新手引导文案
SELECT DISTINCT text FROM text_data WHERE category = 159;          -- 每名马娘的跑法
SELECT text FROM text_data WHERE category = 172 AND "index" = 101; -- 因子名称
```

「证据」列给出的是提取该术语的文本类别号，可复现：

| 类别 | 内容 |
| --- | --- |
| 63 | 新手引导 / 系统功能导语（术语最密集） |
| 131 / 171 | 称号任务、对话条件（出现「干劲“极佳”」等档位词） |
| 159 | 每名马娘的跑法（领跑 / 跟前 / 居中 / 后追） |
| 172 | 因子名称（「速度提升因子」等） |
| 55 / 147 | 属性与适应性的独立标签 |
| 69 | 帮助文本 |
| 140 / 141 | 技能与得分相关文案 |

正文与代码中用**简中官方译名**，需要时可回退到下面的日文原名列查数据。

## 对代码的影响

- `modules/catalog/ui/panel.js`、`manifest.toml`、`api.py` 的界面文案已统一为「协助卡」「耐力」。
- `docs/kb/01` ~ `07` 及 `README.md` / `ROADMAP.md` 的措辞已按本表修订，术语表是唯一依据。
- 数据库列名、API 参数、模块 id 保持英文（`support_card` / `support_cards`），不做中文化。
- 代码里没有中文字典：展示层文案写死在各模块 UI 里，术语变更只需改文案，不动数据层。若后续模块变多，应抽出共享的术语表（单一来源），而不是各模块各写一份。
