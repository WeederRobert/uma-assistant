# 相性模块（关系组 / 六人布局）

`modules/succession` 用 `master.mdb` 的 `succession_relation*` 回答两个问题：

1. **两只马娘共享哪些关系组、合计多少分、落在哪个等级**；
2. **六人继承布局**（目标 + 2 位继承马娘 + 4 位祖父母）按社区计算器口径累加出的总分与等级。

## 数据来源

| 内容 | 来源表 | 快照实测 |
| --- | --- | --- |
| 关系组点数 | `succession_relation`（`relation_type` / `relation_point`） | 2133 组，点数只有 **1 / 2 / 7 / 8** |
| 关系组成员 | `succession_relation_member`（`relation_type` / `chara_id`） | 4527 条，覆盖 **95** 名角色 |
| 等级区间 | `succession_relation_rank`（`relation_rank` / `min` / `max`） | 3 档：0–50 / 51–150 / 151+ |
| 角色名 | `chara_data` + `text_data` 6 | 95 名（快照共 126 名，31 名不在任何组内） |

### 关系组的规模分布（这决定了两人能得多少分）

| 组内人数 | 组数（按点数） | 说明 |
| --- | --- | --- |
| 1 人 | 612（1 点 612 / 2 点 17） | 只有自己，**两人之间永远不共享** |
| 2 人 | 1125（1 点 1053 / 2 点 44 / 8 点 28） | 多半是室友 / 特定关系 |
| 3–9 人 | 约 90 | 小队 / 小圈子 |
| 10–87 人 | 约 30 | 同冠名 / 同队这类大组 |

所以**两只不同马娘的共享关系组通常是 0–12 个、点数合计 0–40**，落在 △ 档；分数高起来主要靠六人布局把多个位置累加。

## 口径

### 两人相性

统计**两只马娘同时存在**的所有关系组，点数之和即该组合的贡献。这个值不是游戏内显示的最终相性：

- 六人布局里它正好等于 **1 号位（父母之一）** 的贡献；
- **不含适性**（马场 / 距离 / 跑法契合）—— 主数据里没有适性表（`%aptitude%` 查不到，`%proper%` 只有赛事侧的出现率表），算不出来也不假设；
- 不含「继承马娘赢过的 G1 有交集」这类额外项。

### 六人布局（社区口径，不是官方公式）

按知识库 06 记录的 BWiki 计算器分槽方式累加：

| 位置 | 计分对象 |
| --- | --- |
| 1 号 | f(目标, 父母 1) |
| 2 号 | f(目标, 父母 2) + f(父母 1, 父母 2) |
| 3 / 4 号 | f(目标, 父母 1, 祖父母)，**祖父母与目标同角色时记 0** |
| 5 / 6 号 | f(目标, 父母 2, 祖父母)，同上 |

其中 f(…) = 同时包含这些角色的所有关系组点数之和。总分按 `succession_relation_rank` 判等级。

布局里的约束与主数据一致：目标与两位继承马娘必须是 **3 个不同角色**（衣装不同也算同一角色）；祖父母不限（可以与目标同角色，但该位置记 0）。

### 等级

| 分数 | 等级 |
| --- | --- |
| 0–50 | △ |
| 51–150 | 〇 |
| 151+ | ⌾ |

等级名来自社区口径（与知识库 06 一致），区间直接取自 `succession_relation_rank`。

## 数据表

| 表 | 用途 |
| --- | --- |
| `succession_relations` | 关系组 → 点数 |
| `succession_members` | 关系组 ↔ 角色（主键 `(relation_type, chara_id)`，另建 `chara_id` 索引） |
| `succession_ranks` | 分数区间 → 等级 |
| `succession_charas` | 参与关系组的角色名 |

来源元信息写 `meta` 的 `succession.catalog_source`（mdb sha256 前缀、`mdb_mtime`、导入时间、条数）；`master.mdb` 更新后启动自动补导入。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/succession/status` | 条数、等级区间、导入来源、`stale`、三条口径说明 |
| GET | `/api/succession/charas?q=&limit=` | 可选角色（只含参与关系组的 95 名） |
| GET | `/api/succession/pairs?a=&b=` | 共享关系组（编号 / 点数 / 组内人数）、合计、等级；同一角色返回 422，未知角色 404 |
| GET | `/api/succession/layout?target=&parent1=&parent2=&g1..g4=` | 六人布局逐位置小计、总分、等级、还缺几个祖父母位 |
| POST | `/api/succession/refresh?force=` | 重新导入 |

## 面板

侧栏「相性」：

- **数据来源**：关系组 / 成员 / 角色条数、三档区间、导入来源与数据版本，`stale` 时提示刷新。
- **两人相性**：两个下拉选马娘 + 计算；显示「共享 N 个关系组 · 点数合计 X」、连加式（`7 + 7 + 2 + …`）、等级 pill，下面是共享关系组卡片网格（编号 / 组内人数 / 点数）。
- **六人继承布局（可选）**：目标 + 父母 ×2 + 祖父母 ×4（可留空），给出逐位置表格（位置 / 组合 / 关系组数 / 小计，同角色记 0 会标注）与总分、等级、缺位提示。
- **口径说明**：三条固定说明（不是最终相性、社区口径、关系组无名称字典）。

## 已知限制

- **关系组没有名称**：`relation_type` 在主数据里没有「室友 / 同冠名」这类文本，面板只显示编号与组内人数；即使显示人数，也无法区分「室友 2 人组」与「其他 2 人组」。
- **不含适性**：见上，主数据没有适性表。
- **不含 G1 交集加成**：需要「继承马娘赢过哪些 G1」，属于玩家育成结果，不在主数据里。
- **等级名是社区口径**：△ / 〇 / ⌾ 与区间阈值来自 BWiki 计算器页面，官方没有公开公式。
- **1 人组恒为 0 贡献**：612 个单角色组不参与任何两人 / 三人组合，属正常数据，不是漏导入。
